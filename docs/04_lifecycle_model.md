# 4. Модель жизненного цикла ИС

## Выбранная модель

Для проекта «Контроль исполнения договоров» применяется **каскадная модель** жизненного цикла информационной системы (ГОСТ 34.601-90). Выбор обусловлен:

- чётко определёнными требованиями на старте проекта;
- учебным характером разработки;
- относительно небольшим объёмом работ;
- отсутствием необходимости частых итераций с заказчиком.

## Этапы жизненного цикла

### Этап 1. Формирование требований к ИС
Определение проблемы ручного контроля договоров, формулирование цели и задач, выявление заинтересованных сторон.

### Этап 2. Разработка концепции ИС
Анализ существующих решений, обоснование необходимости разработки, определение функциональных и нефункциональных требований.

### Этап 3. Техническое задание
Описание структуры данных, ролей пользователей, требований к интерфейсу и производительности.

### Этап 4. Эскизный проект
Проектирование макета интерфейса, определение архитектуры приложения (клиентская часть: HTML + CSS + JS).

### Этап 5. Технический проект
Детализация структуры файлов, описание алгоритмов фильтрации и определения просрочек.

### Этап 6. Рабочая документация
Разработка исходного кода, подготовка README и проектной документации.

### Этап 7. Ввод в действие
Публикация в GitHub, проверка работоспособности, подготовка инструкции запуска.

### Этап 8. Сопровождение ИС
Планирование развития: добавление серверной части, уведомлений, отчётности.

## Схема жизненного цикла

```
Требования → Концепция → ТЗ → Эскизный проект → Технический проект → Разработка → Ввод в действие → Сопровождение
```
